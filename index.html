Normal hours

Working baseline

Normal working hours are used as the baseline for OT calculation. Position-specific hours apply unless Ramadan rules override them.

02
OT calculation

Working vs baseline

OT is calculated from valid biometric Working Hrs and the applicable normal working-hours baseline.

03
Extended dispatch

Dispatch > threshold

Standard threshold is 8:50; Ramadan Muslim staff use 8:30. Working time is capped at dispatched duration.

04
WR override

Rest-day call-in

Planned WR or Dispatched RD/RDOT/OT requires an actual RD/RDOT/OT duty before OT is payable.

Ramadan configuration

Ramadan overtime period

While a roster date falls inside this range, staff with Religion IS get OT calculated purely from Actual Working Hours: OT = MIN(Actual Working Hrs, 8:30) − 6:00, floored at 0 — the scheduled/Dispatched duration is never used to gate or cap this. NO-IS staff are unaffected and keep the standard dispatch-based rules. Update these dates each year — no code changes needed.

Not configured
Holiday configuration

Full-day overtime holidays

For roster dates inside any of the ranges below, OT is calculated directly from the Actual Biometric working time: the full working time (capped at the Dispatched duration, same 12:00 ceiling as normal) counts as OT — no baseline deduction. Applies to all staff regardless of Religion. All four holiday types below share this identical calculation rule. Update these dates each year — no code changes needed.

Attendance verification

Biometric Validation

Upload a biometric transactions report or a daily attendance report with sign-in / sign-out columns (.xlsx, .xls or .csv) to find each staff member's first Entry and last Exit for every attendance period. Records are grouped by staff ID and a continuous 24-hour window — not by calendar date — so overnight shifts that cross midnight stay together while separate shifts are kept apart. Anything that cannot be assigned with confidence is flagged for review instead of guessed.

How records are grouped into attendance periods
  • Records are grouped by staff ID and sorted by exact date and time. The attendance window never resets at midnight.
  • A period starts at an Entry. Its first Entry is the earliest Entry and its last Exit is the latest Exit that follows, even if that Exit falls on the next calendar day.
  • A later Entry joins the same period only if it comes less than the new-shift gap after the previous scan and within the max shift window of the first Entry. Otherwise it starts a new period, so two separate shifts are never merged.
  • An Exit with no open Entry becomes Missing Entry; an Entry with no Exit becomes Missing Exit. Nothing is guessed.
  • Repeated scans seconds apart (several gates in a row) count as one event. Real re-entries, ambiguous gaps, unusually long or short durations and direction glitches are flagged Multiple Records or Needs Review.
  • Attendance-report layout (one row per shift): staff ID is read from column A, name from B, sign-in date from D, sign-in time from F, sign-out date from H and sign-out time from I — blank or unused columns in between are ignored. Each date and time is combined into one date-time, and every row becomes one Entry and one Exit that go through the same rules below. If a file repeats the sign-in date on an overnight sign-out (sign-out time earlier than sign-in time), the sign-out is placed on the next day.
  • Scans the gate denied (a “Result” column other than granted) are not attendance evidence; they are listed under record-level exceptions.

RD/RDOT/OT requirement applies to the WR override rule only (Rule 2): triggers on Planned = WR or on Dispatched showing RD/RDOT/OT, but only pays OT when Dispatched actually contains RD, RDOT or a stand-alone OT code. Extended dispatch (Rule 1) is unaffected by RD/RDOT. Fixed working baseline is position-specific (8:30 for most positions, 10:30 for Train Ambassador, 9:30 for Station Agent, 9:00 for Station Ambassador). Working Hrs above 14:00 are treated as an invalid biometric and disqualify that day from any OT, under either rule. Working time from a valid Actual punch is measured from the Dispatched cell's own scheduled start time (not the Actual sign-on stamp) through to the Actual sign-off. Working Hrs used for OT calculation is capped at 12:00 regardless of what Actual or the file's own Working Hrs implies. Calculated OT under 30 minutes is not payable and is corrected to 0:00. A valid biometric Actual record must match HH:MM:SS - HH:MM:SS; whenever Actual is valid, the worked duration is always computed directly from it (correctly handling overnight shifts) rather than trusting the source file's own Working Hrs column, which has shown itself unreliable for overnight shifts (N/A, or even an incorrect 0:00). The file's own Working Hrs is only used as a fallback when Actual itself is missing or malformed.
